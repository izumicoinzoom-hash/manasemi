事務局版「講師会通信」の制作フローと、AIとの付き合い方を全公開します。

この文書は、講師会通信（No.01 / No.1.5 ...）が どんな素材から、どんな工程を経て、誰の手によって仕上がっているか を、できるだけ素のまま開示するためのページです。AIをどう使い、どこまで人間が判断し、誤りが見つかったらどう直すか — その全体像を共有することで、講師の皆さまが安心して指摘・依頼できる土台を作りたいと考えています。

01なぜ「事務局版」を作るのか

講師会のリハや議論は、毎回密度が高い。録音を聞き返せばすべて残っているとはいえ、120分の録音を再生する余裕は誰にもありません。一方で、当日参加できなかった講師、後から振り返りたい講師、本番運営に活かしたい受講生サイドにとって、「今日決まったことは何か」「保留になったのは何か」を短時間で把握できる形があると、議論の積み上げが効きます。

そこで本通信は、「議事録」と「読み物」の中間 を目指しています。固有名詞・時間・決定事項を正確に残しながら、思想的な手触り（議論の温度感、なぜそう決まったか）も残す。それを当日の写真と一緒に1枚のページに収める — それが事務局版の役割です。

議事録だけだと、決まったことしか残らない。
けれど、決まる手前で交わされた言葉にこそ、マネゼミ思想の手触りがある 制作方針

02素材 — 何を元にしているか

1号を仕上げるのに使う素材は、おおむね次の4種類です。

素材取得元役割
録音・自動文字起こしCircleBack（AI議事録サービス）発言の事実関係・引用元（一次資料）
当日のスライドGoogle Slides（講師作成）講義の骨格・図表の引用元
当日の進行プログラムGoogle Docs（事務局作成）タイムテーブル・本講のねらい
会場写真事務局スマホ撮影誌面の臨場感・会場記録

このうち もっとも重要なのは録音 です。引用するセリフ、決定の経緯、未確定で保留にした論点 — どれもCircleBackが返してくる文字起こしを直接の根拠にしています。

03制作フロー — 6つのステップ

1号を仕上げるまで、最短で約60分（内訳：録音処理 約20分／AI下書き生成 約15分／事務局編集・写真配置 約25分）。フローは次のとおりです。

SOURCE（一次素材） AI（自動処理） HUMAN（事務局判断） DEPLOY（公開・配信）

各ステップの中身

STEP 01 — SOURCE
録音

会議をCircleBackで録音。ハイブリッド開催ならZOOMアプリ経由、対面なら端末を真ん中に置いて拾います。

STEP 02 — AI
自動文字起こし

CircleBackが話者分離・要約・アクションアイテム抽出までを自動で実行。約20分の処理で読める形に。

STEP 03 — AI
記事の素案生成

事務局がClaudeに「議事録＋スライド＋プログラム」を渡し、記事の骨格・引用・テーブルを下書き。

STEP 04 — HUMAN
事務局編集

運営参謀が固有名詞・漢字表記・事実関係を確認。違和感のある箇所を修正し、過去号の表記揺れも吸収。

STEP 05 — DEPLOY
GitHub Pushで公開

HTMLをマネゼミ用GitHubリポジトリにPush。GitHub Pagesが自動で静的サイトとして配信します。

STEP 06 — DEPLOY
LINEで一斉案内

事務局Botから講師会LINEグループへURLを配信。「AIによる下書き」と明記し、訂正窓口を毎回案内。

04AIが担う部分・担わない部分

AIは「全部やる」のでも「単なるサポート」でもありません。下書きまでがAI、判断は人 という線引きで使い分けています。

AIが担うこと
  • 録音の話者分離・文字起こし
  • 会議要約・アクションアイテム抽出
  • 記事構成の素案（見出し・引用配置・テーブル化）
  • HTMLマークアップ・デザイン継承
  • 誤字・表記揺れの一次チェック
AIが担わないこと（事務局判断）
  • 固有名詞の漢字表記（福嶋／田﨑 など）
  • 誰の発言かの最終確定
  • 非公開にすべき情報の取捨
  • トーン・敬称の最終調整
  • 配信タイミング・宛先の判断
大事な前提：AIの文字起こしには 聞き間違い・誤字・話者誤認 が含まれます。たとえば「マネゼミ」を「真似ゼミ」と誤変換したり、似た音の苗字を取り違えたりすることが珍しくありません。だからこそ 事務局編集の工程が省けない、というのが今の運用方針です。

05レビューと修正のサイクル

記事は 公開して終わりではなく、公開して始まる 形にしています。LINEで配信後、講師の皆さまから次のような指摘をいただくのが想定通りの動きです。

  • 「この発言、自分じゃないよ」 → 話者ラベルを匿名化／訂正
  • 「ここはニュアンスが違う」 → 該当箇所を書き直す or 引用ごと削除
  • 「この用語、正しくはこっち」 → 表記を統一して再デプロイ
  • 「この場面、自分は写りたくない」 → 写真を差し替え or トリミング

指摘をいただいたら、原則 当日中〜翌営業日中に修正＋再デプロイ。修正の事実はLINEでも案内します。たとえば本号（No.1.5）は配信後、光澤氏から次のような指摘をいただき、その日のうちに反映しました。

※ 以下の引用は、光澤氏ご本人の確認・同意のうえで掲載しています。

1点、マネゼミ目的のところ「養成」「育成」が混在しています。
あと、結果と成果の言い回し、松尾講師の言い方から抽出するとこうかも：
結果 ＝ そこで完結する（良い結果も悪い結果もある）
成果 ＝ 結果を経て広がる ＝ 繋がる（自分や他の社員にも伝わり残っていくもの） 光澤氏（講師会内での指摘・要約／本人確認済）

この指摘を受けて、記事内の「養成」を 「育成」に統一、成果の定義を 光澤氏の二段定義 に置き換えています。修正履歴は、リポジトリ上のコミット履歴で誰でも追跡できる状態です。

06取り扱い・コンプライアンス

公開範囲とURLの扱い

記事ページには noindex, nofollow を設定。Google検索などには載らない、知っている人だけが辿れるURLです。ただし URLを知っていれば誰でも見られる 状態のため、機微な情報は最初から書きません。外部SNSや公開チャットへの転載はお控えください。受講生・関係者の安全のためのご協力をお願いします。

個人情報の扱い

  • 会社名・役職は本人が普段公にしているレベルまで
  • 住所・電話番号・個別の事業数値などは記載しない
  • 受講生側の発言・写真は、本人合意なしには載せない
  • 写真は背景の偶発的な情報（看板・私物）に配慮

AI生成である旨の明示

記事フッターおよびLINE配信文面に 「AIによる議事録・録音の要約をベースに編集している」 旨を明記。誤りが含まれる可能性と、訂正窓口（事務局）を毎回ご案内しています。

削除・訂正のご依頼窓口

「該当箇所を削除してほしい」「この号自体を非公開にしてほしい」というご要望は、内容を問わず 事務局にて即時対応 します。事実関係の確認や代替案の検討は、削除後に改めて行います。

  • 講師会LINEグループ内で運営参謀宛にDM、または事務局Bot宛にメッセージ
  • 原則 24時間以内に該当箇所を非公開化 し、その後内容確認のうえ修正版を再公開

データの保持と削除

  • 録音・自動文字起こし（CircleBack）は 事務局アカウント内にのみ保管。第三者と共有しません
  • 本ページ・本体記事の公開停止依頼があれば、リポジトリ側からも該当ファイルを削除（コミット履歴は残るため、必要に応じて履歴書き換えも対応）

07これからの改善

運用しながら気づいたことを、少しずつ織り込んでいきます。

  • 話者ラベルの精度：CircleBack側の話者識別を講師ごとに学習させ、「議論の中で」「複数から」という匿名表記を減らす
  • 修正履歴の見える化：記事末尾に「修正履歴」セクションを置き、どの号でどう直したかを残す
  • テンプレ整備：講師会通信のスタイルを共通CSSに切り出し、号ごとの差分だけで書ける形に
  • 第1講本番号の準備：5/16 本番のレポートを No.02 として発行予定

EXTRA制作の様子をYouTubeで公開予定

少しメタな話になりますが、本ページを書いている過程自体も、動画として記録しています。録音 → AI要約 → 事務局編集 → GitHub Push → Pages公開 → LINE配信、という一連の流れを実際にどう進めているか、画面と手元の様子を含めて撮影し、後日YouTubeに公開予定 です。

文章で説明されてもピンとこない、実際にどんな操作をしているのか見てみたい、という方に向けたコンテンツです。AIをどう使い、どこで人が判断し、修正サイクルがどう回るのか — 「事務局の仕事の中身」をそのまま見ていただける動画になります。

公開先URL：YouTubeへのアップロード完了後、本ページ末尾に追記します。チャンネル名・限定公開／一般公開の方針も、アップ時に併せて明記します。

08結びに

講師会通信は、議論の温度を残すための器です。AIは効率を稼ぐ道具として使っていますが、「何を残し、何を残さないか」の判断は、いつも人の側 にあります。気になる点・直したい点があれば、いつでも事務局までお寄せください。読みやすさも、正確さも、そこから前進します。

本ページ自体への指摘・提案も歓迎します。「ここの説明がわかりにくい」「この方針には異論がある」「もっと開示してほしい項目がある」 — どんな粒度のフィードバックでも受け止めます。
